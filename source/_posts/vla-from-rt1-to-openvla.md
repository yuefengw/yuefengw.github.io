最近在系统学习 Vision-Language-Action（VLA）。把几篇论文连起来读之后，我发现真正值得记住的并不是某个模型的成功率，而是一条逐渐清晰的技术主线：**机器人策略如何借用大模型的表示与训练范式，从单一机器人上的模仿学习，走向能够吸收互联网知识和多机器人经验的通用策略。**

<!-- more -->

这条路线可以先压缩成四句话：

1. **RT-1** 证明大规模、多任务真实机器人数据可以训练一个通用策略；
2. **RT-2** 把机器人动作表示成 Token，让预训练 VLM 直接成为 VLA；
3. **Open X-Embodiment / RT-X** 把数据规模化从“单一机器人”推进到“跨机器人平台”；
4. **OpenVLA** 将这条路线做成可下载、可微调、可部署的开放模型。

本文按照这条主线，重点回答几个我学习时最困惑的问题：动作为什么能变成 Token？256 个 Bin 到底怎么对应真实动作？不同机器人动作空间不一致，数据为什么还能混合训练？OpenVLA 又在 RT-2-X 之上改变了什么？

## 1. VLA 到底是什么

传统机器人系统往往把感知、任务规划和控制拆成多个模块：视觉模型识别环境，语言模型解释任务，策略或运动规划器再输出控制命令。模块化方案边界清楚，但也带来一个问题：视觉语言模型在互联网数据中学到的丰富语义知识，很难原封不动地传到低层动作策略里。

VLA 试图把三件事放进同一个序列建模框架：

```text
图像观察 + 自然语言指令 -> 动作
Vision    + Language      -> Action
```

模型不再只回答“画面里有什么”，而要回答“机器人下一步应该做什么”。如果动作也被编码成 Token，那么这个问题在形式上就和 VLM 的文本生成非常接近：给定图像和文本上下文，自回归地预测下一个 Token。

但形式统一不代表问题已经解决。一个 VLA 至少同时面对四个难题：

- **数据**：真实机器人数据昂贵，规模远小于互联网图文数据；
- **动作表示**：连续控制量必须转换成模型可以学习和执行的形式；
- **泛化**：模型既要认识新物体、新场景，也要把语义理解落实成物理动作；
- **部署**：大模型的推理延迟必须满足闭环控制要求。

RT 系列和 OpenVLA 的演进，本质上就是不断扩大这四个问题的可解范围。

## 2. RT-1：先证明机器人数据可以规模化

RT-1 还不是后来意义上的大型 VLA，但它奠定了重要的训练范式：把大量真实机器人示范统一成“图像 + 指令 -> 动作”的序列预测问题，用一个模型学习多任务策略。

它的意义不在于引入互联网知识，而在于证明：当机器人示范覆盖足够多的技能、物体和环境变化时，一个 Transformer 策略可以在同一套参数里容纳大量任务，并对新组合产生一定泛化。

这一步留下了两个关键遗产：

1. 使用自然语言作为统一的任务接口；
2. 将连续机器人动作离散化，转换成分类或 Token 预测。

RT-2 沿用了这套机器人数据和动作接口，但把模型骨干从专用机器人策略替换成了互联网规模预训练的视觉语言模型。于是问题从“机器人数据能否规模化”变成了“互联网知识能否迁移到机器人控制”。

## 3. RT-2：把机器人动作当成一种语言

RT-2 最精炼的思想是：**动作不是挂在语言模型之外的额外回归头，而是模型词表里的一组特殊符号。**

![RT-2 将互联网视觉语言数据和机器人动作数据放进同一个 VLA 中联合训练](/images/posts/vla-roadmap/rt2-overview.webp)

上图来自 RT-2 论文 Figure 1。训练时，模型同时看到互联网视觉语言任务和机器人示范；推理时，模型输出动作 Token，系统再将其反 Token 化为连续控制量，并在真实机器人上形成闭环。

### 3.1 RT-2 的动作空间

RT-2 沿用 RT-1 的末端执行器动作表示，而不是直接输出每个关节角。一个时间步包含：

```text
[terminate, Δx, Δy, Δz, Δrx, Δry, Δrz, gripper]
```

其中六个维度描述末端执行器的位置与旋转增量，一个维度描述夹爪开合程度，`terminate` 是任务是否完成的离散指令。

末端执行器表示的价值在于，它比具体关节角更接近“手向哪里移动、如何旋转、是否抓取”这种任务层语义，也较少绑定某一种机械臂结构。但它并没有消除机器人运动学：真实执行时仍需要控制器把末端位姿增量转换成对应机器人的关节命令。

### 3.2 连续动作如何变成 256 个 Bin

除 `terminate` 外，每个连续维度都被**独立、均匀地划分为 256 个区间**。设某个动作维度的范围为 `[a_min, a_max]`，实际动作为 `a`，可以把量化过程写成：

```text
bin = clip(floor((a - a_min) / (a_max - a_min) * 256), 0, 255)
```

反量化时，可以取对应区间的中心：

```text
a_hat = a_min + (bin + 0.5) / 256 * (a_max - a_min)
```

举一个只用于解释原理的例子。假设 X 方向每步位移范围为 `[-0.05, 0.05] m`，那么每个 Bin 的宽度约为 `0.391 mm`。`Δx = 0.01 m` 会落入 Bin 153，推理时再由 Bin 153 恢复成该区间中心附近的位移。

这里有三个容易误解的点：

- 256 个 Bin 是**每个连续维度各有 256 个**，不是整个动作向量只有 256 种动作；
- 相同的 Bin 编号在不同维度上代表不同物理量，X 位移的 Bin 128 和夹爪的 Bin 128 没有相同含义；
- 上面的 `±5 cm` 只是示意，RT-2 正文并未公布所有维度的完整最小值与最大值。

独立分桶的优点是实现简单、能直接复用分类式输出；代价则是量化误差，而且各维度被分别建模，动作之间的连续结构主要依赖 Transformer 自己学习。

### 3.3 Bin 如何映射到 Token

RT-2 使用了两种基础 VLM，对应两种 Token 映射方式：

| 模型 | 动作 Token 的构造方式 |
| :-- | :-- |
| RT-2-PaLI-X | PaLI-X 对 0 到 1000 的整数有独立 Token，直接用整数 Token 表示 Bin 编号 |
| RT-2-PaLM-E | 从原词表中选取 256 个最低频 Token，重新赋予它们动作含义 |

于是，一条专家示范中的连续动作会变成一串整数或特殊 Token。模型使用普通的自回归交叉熵目标，逐个预测动作维度。动作任务解码时，词表会被约束在合法动作 Token 范围内，防止模型突然输出一段自然语言。

这种“合法”只是格式合法，不等于物理安全。受约束解码不能保证机器人不会碰撞，也不能替代安全控制器、限位和异常检测。

### 3.4 为什么要 Co-fine-tuning

如果只用机器人数据微调，VLM 可能在狭窄的数据分布上遗忘原有的视觉语言能力。RT-2 因此把机器人轨迹与原始互联网视觉语言任务混合训练：

```text
Web 图文任务：维持视觉、语言和常识能力
机器人示范：学习动作 Token 与物理行为
                    ↓
              同一个 VLA 模型
```

这也是 RT-2 能把“疲惫的人适合喝什么”这类互联网语义知识转成真实抓取行为的关键。论文的实验重点不是已见任务上小幅领先，而是未见物体、背景、环境和语义任务上的明显提升。

不过要准确理解“涌现能力”：RT-2 并不是凭互联网知识凭空学会全新的低层运动技能。它更多是在机器人数据已经提供的抓取、移动、放置等技能上，利用 Web 知识选择新的对象、位置或组合方式。

## 4. Open X-Embodiment / RT-X：让机器人学习其他机器人的经验

RT-2 主要扩大了**知识来源**，Open X-Embodiment 则进一步扩大了**机器人经验来源**。

不同实验室的数据原本高度割裂：机械臂结构、相机位置、控制频率、坐标系、动作定义和语言标注都可能不同。Open X-Embodiment 的核心贡献，是把来自 21 个机构的 60 个数据集整理成统一数据集合，包含超过 100 万条轨迹、22 种机器人形态和 527 种技能。

![Open X-Embodiment 汇集多机构、多机器人形态和多技能数据](/images/posts/vla-roadmap/open-x-embodiment.webp)

这项工作的长期价值不仅是 RT-1-X 或 RT-2-X 两个模型，更是建立了类似机器人学习“ImageNet”的开放数据基础设施。

### 4.1 跨机器人动作真的统一了吗

一个常见说法是，Open X-Embodiment 把不同机器人的动作都统一成 7 维末端执行器动作。这个说法只对了一半。

数据处理确实尽量采用统一接口：

```text
[Δx, Δy, Δz, Δroll, Δpitch, Δyaw, gripper]
```

图像被调整到统一输入规格，动作按各数据集的统计量归一化，再离散为 256 个 Bin。但论文明确指出，不同数据集之间仍可能存在：

- 末端执行器坐标系不一致；
- 绝对位置、相对位置或速度控制定义不同；
- 控制频率和时间尺度不同；
- 相同数值在不同机器人上产生不同的真实运动。

因此 RT-X 并没有建立一个严格对齐的全球物理坐标系。更准确地说，它提供了一个**足够相似的学习接口**，让模型在保留数据集或机器人上下文的情况下，学习跨平台共享的视觉、语言和操作规律。

### 4.2 RT-1-X 与 RT-2-X

两种模型都使用多机器人数据，但侧重点不同：

| 模型 | 基础 | 训练数据 | 主要目标 |
| :-- | :-- | :-- | :-- |
| RT-1-X | RT-1 | 多机器人示范 | 验证跨机器人数据能否为策略带来正迁移 |
| RT-2-X | RT-2 / 预训练 VLM | 多机器人示范 + Web 数据 | 同时获得语义泛化与跨机器人技能迁移 |

在五个小规模数据领域的实验中，RT-1-X 平均成功率达到 63%，高于 Original Method 的 41% 和单一数据源 RT-1 的 44%。但在部分大规模数据任务上，RT-1-X 反而不如只使用目标机器人数据的 RT-1；论文将其归因于较小模型面对高度异质数据时的欠拟合。

这个结果很重要：**数据更多不必然更好，数据多样性必须与模型容量、采样策略和动作对齐能力一起增长。**

RT-2-X 最有代表性的结果是跨机器人技能迁移。在 Google Robot 上测试只出现在 Bridge/WidowX 数据中的技能时，RT-2-X 的成功率从 RT-2 的 27.3% 提升到 75.8%。这说明多机器人混合训练不只是改善视觉泛化，它可以让一台机器人借用另一台机器人的操作经验。

但这仍不等于“任意机器人零样本控制”。论文中的数据集包含 22 种 embodiment，而 RT-X 模型实验使用的是其中一部分平台；对完全未见过的新机器人、差异巨大的传感器或执行器，仍需要适配。

## 5. OpenVLA：把 VLA 变成开放、可微调的基础模型

RT-2-X 展示了强大能力，但模型和训练体系并未完全开放。OpenVLA 的目标是把同一条技术路线变成研究者真正可以下载、微调和部署的模型。

![OpenVLA 由双视觉编码器、投影层、Llama 2 7B 和动作反 Token 化模块构成](/images/posts/vla-roadmap/openvla-architecture.webp)

OpenVLA 是一个 7B 参数模型，在 Open X-Embodiment 的 970k 条机器人轨迹上训练。它基于 Prismatic VLM，主要包含：

1. **DINOv2 + SigLIP 双视觉编码器**：前者补充空间特征，后者提供较强语义特征；
2. **MLP Projector**：把视觉特征映射进语言模型的嵌入空间；
3. **Llama 2 7B**：接收视觉与语言 Token，并自回归预测离散动作 Token；
4. **Action De-tokenizer**：将 Token 恢复为 7 维机器人控制动作。

与 RT-2 一样，OpenVLA 仍把每个连续动作维度离散成 256 个 Bin。不过它不直接复用普通数字 Token，而是覆盖 Llama 分词器中最后 256 个、也是使用最少的 Token 位置作为动作词表。另一个重要差异是，OpenVLA 用训练数据的第 1 与第 99 百分位确定各维度的分桶边界，而不是直接使用最小值和最大值，从而减少离群动作对有效量化精度的影响。

OpenVLA 的价值主要体现在三个方面。

### 5.1 更小但有竞争力

论文在 WidowX/BridgeData V2 和 Google Robot 上对比 RT-1-X、RT-2-X 与 Octo。OpenVLA 只有 7B 参数，在 Google Robot 评估中与 55B 的 RT-2-X 表现相近，并在 BridgeData V2 评估中明显优于 RT-2-X。

这不应简单解释成“7B 架构一定优于 55B”。论文指出，结果还受更大的机器人训练集、数据清洗和双视觉编码器等因素影响；RT-2-X 在强语义泛化任务上仍有优势，因为它使用更大规模的互联网预训练，并在微调时继续混合 Web 数据。

### 5.2 能适配新机器人和新任务

OpenVLA 系统评估了对新 Franka 机器人任务的微调。在每个任务只有 10 到 150 条示范的条件下，它在多指令、含干扰物、依赖语言落地的任务上显示出预训练通用策略的优势。

论文也给出了一个很实用的结论：LoRA rank 32 只训练约 1.4% 参数，成功率接近全量微调，并把训练从 8 张 A100 降到单张 A100 上约 10 到 15 小时。对于希望在自有机器人上验证 VLA 的研究者，这比单纯的排行榜结果更有意义。

### 5.3 量化让部署门槛下降

OpenVLA 的 bfloat16 推理约占 16.8 GB 显存；4-bit 量化可降到约 7.0 GB，并在论文的 Bridge 任务上保持相近成功率。8-bit 量化反而因额外开销降低控制频率，导致真实机器人性能下降。

这个结果提醒我：机器人部署不能只看离线 Token 准确率。推理延迟会改变闭环控制系统的动态特性，同一个模型在 1 Hz 和 5 Hz 下可能表现完全不同。

## 6. 把四项工作连起来看

到这里，可以用一张概念表概括演进关系：

| 工作 | 扩展的核心维度 | 关键问题 |
| :-- | :-- | :-- |
| RT-1 | 单机器人上的任务与数据规模 | 一个策略能否学习大量真实机器人任务？ |
| RT-2 | 互联网视觉语言知识 | Web 知识能否通过动作 Token 迁移到控制？ |
| RT-X | 机器人平台与数据多样性 | 一台机器人能否学习其他机器人的经验？ |
| OpenVLA | 开放性、可微调与可部署性 | VLA 能否成为社区可复用的基础模型？ |

也可以把它写成一条更抽象的路线：

```text
Robot Data Scaling
        ↓
Web Knowledge Transfer
        ↓
Cross-Embodiment Data Scaling
        ↓
Open and Adaptable VLA
```

这里始终贯穿着同一个技巧：把动作包装成语言模型可以预测的 Token。但随着数据和任务复杂度增加，这个技巧的局限也越来越明显。

## 7. 离散动作 Token 的优势与边界

256-bin 离散化为什么能长期被沿用？

- 与 LLM 的分类式、自回归输出天然兼容；
- 不需要额外设计连续动作解码器；
- 每个动作维度的训练目标清楚、稳定；
- 可以直接利用成熟的 Tokenizer、交叉熵训练和受约束解码工具链。

但它也有明显边界：

- **量化误差**：精细控制会受 Bin 宽度限制；
- **逐 Token 延迟**：一个动作要生成多个 Token，大模型推理频率较低；
- **缺少时间结构**：逐时刻预测单步动作，容易产生抖动或误差累积；
- **多模态动作分布**：面对“向左绕或向右绕都可行”时，单一离散预测未必能表达丰富分布；
- **跨 embodiment 对齐有限**：统一维度不等于统一物理语义。

这也解释了为什么后续 VLA 研究越来越关注 Action Chunking、连续动作生成、Diffusion Policy、分层控制和更丰富的动作 Tokenizer。研究方向不是简单抛弃 RT-2，而是在保留大模型语义能力的同时，补上高频、平滑、精细控制的短板。

## 8. 我目前形成的三个认识

### 8.1 VLA 的“通用”主要来自数据接口，而不是机器人天然相同

不同机器人并没有因为都使用 7D 动作就真正共享同一个物理动作空间。所谓通用策略，是模型在大量异质数据中学习到可复用结构，再通过数据集约定、归一化、反归一化和底层控制器落到具体硬件上。

### 8.2 语义泛化和运动技能泛化是两件事

VLM 预训练擅长告诉机器人“应该操作哪个对象”，多机器人示范则补充“这种操作可以怎样完成”。RT-2 与 RT-2-X 的差异恰好揭示了这两个来源：Web 知识改善语义选择，跨机器人数据可以带来新的操作技能。

### 8.3 真正的瓶颈正在从模型结构转向数据与系统

动作定义、时间同步、相机选择、语言标注、数据混合比例、控制频率和安全机制，都会直接决定 VLA 的实际效果。模型规模很重要，但机器人基础模型不可能只靠扩大参数量解决异质数据的所有问题。

## 9. 下一步值得继续追的方向

沿着这条主线继续学习，我认为最值得深入的有四个问题：

1. **动作表示**：离散 Token、连续回归、Diffusion、VQ 和 Action Chunking 分别适合什么控制任务？
2. **跨机器人对齐**：怎样显式建模坐标系、控制频率、运动学与 embodiment 差异？
3. **数据混合**：如何避免大数据集淹没小数据集，并平衡正迁移与负迁移？
4. **闭环部署**：模型延迟、控制频率、观测历史和安全控制怎样共同设计？

如果只保留一句总结，我会这样理解 VLA：

> VLA 不是“让 LLM 输出几个机器人数字”这么简单，而是尝试建立一种统一接口，让互联网知识、多机器人经验和真实世界反馈能够在同一个策略中被学习和调用。
